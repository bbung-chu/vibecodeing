# 대학생 강의 정리 앱 설계

- 작성일: 2026-10-14
- 상태: 검토 대기

## 1. 목적

대학생이 강의자료, 시간표, 시험과 과제 일정을 한곳에서 관리하는 웹앱이다.
강의자료를 내려받아도 어디에 저장할지 애매하고, 시간표와 일정이 여러 앱에 흩어져 있는 문제를 푼다.

- 사용자: 먼저 만든 사람 본인이 쓰고, 써 보고 괜찮으면 다른 대학생에게도 배포한다.
- 성공 기준: 학기 초에 시간표만 넣으면 강의별 자료 폴더가 준비되고, 시험과 과제 날짜를 넣으면 홈과 일정에서 D-day로 보인다.

## 2. 범위

### 포함
1. 자료 정리: 학년(1~4) → 학기(1, 2) → 강의 폴더에 파일을 올리고 내려받는다.
2. 시간표: 에브리타임처럼 주간 표에 강의를 넣는다.
3. 일정: 시험, 과제, 공모전, 개인 일정을 달력과 목록으로 본다.
4. 구글 로그인과 사용자별 데이터 분리.

### 제외 (이번 버전에서 만들지 않음)
- 자료 위 필기(손글씨, 텍스트, 밑줄). 나중 버전 후보.
- 다른 사용자와 자료나 시간표 공유.
- 이메일, 푸시 알림.
- 휴대폰 전용 화면. 노트북 화면 기준으로 만들고, 좁은 화면에서는 깨지지 않을 정도만 맞춘다.
- 에브리타임 시간표 가져오기.

## 3. 핵심 흐름

1. 구글로 로그인한다.
2. 학기를 만든다 (예: 2학년 1학기). 같은 학년과 학기 조합은 한 번만 만들 수 있다.
3. 시간표에서 강의를 추가한다. 이 순간 자료 트리에 그 강의 폴더가 생긴다.
4. 강의 폴더에 파일을 직접 올린다.
5. 강의 설정에서 중간고사, 기말고사 날짜와 과제를 입력한다. 입력하는 즉시 일정에 나타난다.
6. 공모전이나 개인 일정은 일정 화면에서 직접 추가한다.
7. 홈에서 다가오는 일정을 D-day 순으로 확인한다.

## 4. 화면

노트북 화면 기준. 왼쪽에 고정 메뉴, 오른쪽에 내용. 화면 위쪽에 현재 학기 선택 상자가 있고, 시간표와 자료는 선택된 학기를 기준으로 보여 준다.

| 화면 | 내용 |
|---|---|
| 홈 | 오늘 수업 목록, 앞으로 30일 안의 일정을 D-day 순으로. 지난 일정은 숨긴다. |
| 시간표 | 월~금 주간 표(토요일 수업이 있으면 토요일 칸 추가). 기본 시간대 09:00~18:00, 그 밖의 수업이 있으면 범위를 늘린다. 강의 블록을 누르면 강의 화면으로 간다. |
| 자료 | 학년 → 학기 → 강의 트리. 강의를 고르면 파일 목록(이름, 크기, 올린 날짜). 올리기, 내려받기, 이름 바꾸기, 삭제. PDF와 이미지는 브라우저에서 미리보기, 나머지는 내려받기. |
| 강의 | 강의 정보 수정(이름, 교수, 강의실, 색상, 수업 시간), 중간고사와 기말고사 날짜와 시간, 과제 목록(제목, 마감 일시, 여러 개). 강의 삭제. |
| 일정 | 월간 달력과 목록 보기 전환. 강의에서 온 일정은 강의 색, 공모전과 개인 일정은 고정 색. 공모전, 개인 일정 추가, 수정, 삭제. 강의에서 온 일정은 누르면 해당 강의 화면으로 가서 수정한다. |

## 5. 데이터

모든 표에 `user_id`가 있고, Supabase 행 수준 보안(RLS)으로 본인 행만 읽고 쓸 수 있다.

| 표 | 주요 열 | 비고 |
|---|---|---|
| `semesters` | id, user_id, year(1~4), term(1, 2) | (user_id, year, term) 중복 불가 |
| `courses` | id, user_id, semester_id, name, professor, room, color | 학기 삭제 시 함께 삭제 |
| `course_slots` | id, course_id, day_of_week(1=월~6=토), start_time, end_time | 강의 하나에 여러 개 |
| `events` | id, user_id, course_id(없을 수 있음), kind, title, starts_at | kind: midterm, final, assignment, contest, personal |
| `files` | id, user_id, course_id, name, size_bytes, mime_type, storage_path, created_at | 실제 파일은 Supabase Storage |

규칙:
- 강의마다 midterm, final 일정은 최대 1개씩. assignment는 여러 개.
- contest, personal 일정은 course_id가 비어 있다. midterm, final, assignment는 course_id가 반드시 있다.
- 강의를 지우면 그 강의의 수업 시간, 일정, 파일 기록과 저장소의 실제 파일까지 지운다. 지우기 전에 확인 창을 띄운다. 학기 삭제도 같은 방식.
- 날짜와 시간은 모두 한국 시간(Asia/Seoul) 기준으로 보여 주고, D-day도 한국 날짜 기준으로 계산한다(당일은 D-day, 다음 날은 D-1).

### 파일 저장
- 비공개 버킷 하나, 경로는 `{user_id}/{course_id}/{file_id}`. 저장소 정책으로 경로 첫 폴더가 본인 user_id일 때만 접근 허용.
- 파일 하나 최대 50MB.
- 허용 형식: pdf, ppt, pptx, doc, docx, hwp, hwpx, xls, xlsx, txt, png, jpg, jpeg, zip.
- 내려받기와 미리보기는 짧게 유효한 서명 URL로 한다.

## 6. 기술 구성

- Next.js(App Router, TypeScript), Tailwind CSS.
- Supabase: 구글 로그인(Auth), Postgres, Storage. 데이터베이스 구조는 마이그레이션 파일로 저장소에 남긴다.
- Vercel 배포. Supabase 주소와 키는 환경 변수로만 넣고 저장소에 올리지 않는다.
- 단위 테스트 Vitest, 브라우저 테스트 Playwright.

코드 구조는 기능 단위로 나눈다: `semesters`, `courses`(수업 시간 포함), `events`, `files`, 그리고 D-day 계산, 시간 겹침 검사, 파일 검사 같은 순수 함수는 화면과 분리해 따로 테스트한다.

## 7. 오류 처리

- 파일이 50MB를 넘거나 허용 형식이 아니면 올리기 전에 막고 이유를 보여 준다.
- 같은 학기 안에서 수업 시간이 겹치면 경고하고, 그래도 저장할지 묻는다(재수강, 청강 등 예외가 있으므로 막지는 않는다).
- 수업 시간은 시작이 끝보다 앞서야 저장된다.
- 저장, 업로드 실패 시 화면에 이유를 보여 주고 다시 시도할 수 있게 한다. 업로드 중 실패하면 데이터베이스 기록이 남지 않게 한다.
- 로그인이 풀리면 로그인 화면으로 보낸다.

## 8. 테스트

- 먼저 테스트를 쓰고 구현한다(TDD).
- 단위 테스트: D-day 계산(한국 날짜 경계 포함), 수업 시간 겹침 검사, 파일 크기와 형식 검사, 시간표 표시 범위 계산.
- 데이터베이스: 다른 사용자의 행과 파일에 접근할 수 없는지 확인.
- 브라우저 테스트: 로그인 → 학기 만들기 → 강의 추가 → 자료 폴더 생김 → 파일 올리기 → 중간고사 날짜 입력 → 일정과 홈에 표시.

## 9. 사용자가 할 일

배포 단계에서 Supabase 가입과 프로젝트 생성, Vercel 가입, 구글 로그인용 OAuth 설정이 필요하다. 그 시점에 단계별 안내를 따로 제공한다.
